# Proposal

## Why

Появляется новый сервис `wallet-mcp`: MCP-сервер, через который LM Studio, а позже
любой MCP-клиент (Claude Code, Claude Desktop) отвечает на вопросы о тратах
(«сколько ушло на няню и еду в сентябре»). Клиент держит в конфиге (`mcp.json`)
статичный заголовок `Authorization` и не умеет ни входить через Google, ни
ротировать refresh-токен. Access-JWT живёт 15 минут, поэтому его в конфиг не
положить, а долгоживущий JWT нельзя отозвать: сервисы проверяют только подпись.
Нужен отзываемый долгоживущий токен только на чтение, который `wallet-mcp`
меняет на короткий JWT. Так уже устроен бот (`/internal/telegram/token`).

## What Changes

- **Персональный MCP-токен.** Новая ручка `POST /auth/mcp-tokens` выпускает
  непрозрачный токен `wmcp_<base64url от 32 случайных байт>` для принятого токена
  пользователя. Токен показывается один раз. Хранится только его SHA-256-хэш в
  Redis, рядом с refresh-токенами. Имя задаёт пользователь, например «LM Studio
  дома». У пользователя может быть несколько MCP-токенов, у каждого свой
  `device_id`.
- **Скользящий срок с потолком.** Токен умирает после 30 дней без использования.
  Каждый успешный обмен продлевает его, но не дальше абсолютного потолка в
  90 дней от выпуска. Продления за потолок нет, нужно выпустить новый токен.
- **Обмен на короткий JWT.** Новая ручка `POST /internal/mcp/token` (не
  проксируется гейтвеем) принимает MCP-токен и выпускает JWT RS256: `aud` =
  `["wallet-report"]`, `scope` = `reports:read`, `platform` = `mcp`, `device_id`
  токена, `exp` = `iat` + 300, **без claim `role`**. Как и токен бота, этот JWT
  не регистрируется активным access-токеном google-auth. Узкий `aud`/`scope` и
  отсутствие `role` не дают MCP ни писать в кошелёк, ни читать чужой леджер
  через админский `as_user_id` в wallet-report.
- **MCP-токены — это сессии устройств.** Они видны в `GET /auth/devices`
  (`platform: "mcp"`) и отзываются существующими `POST /auth/devices/revoke` и
  `revoke-others`. В списке сессий появляются время последнего использования и
  срок действия.
- Вне объёма: OAuth 2.1 по спецификации MCP (authorization server, экран
  согласия, DCR) — отдельный change позже, задняя половина (обмен) та же.
  Токены с правом записи (клиентский разбор выписок) — тоже позже.

## Capabilities

### New Capabilities
- `mcp-tokens`: выпуск персонального MCP-токена, его скользящий срок с
  потолком и обмен на короткий read-only JWT для `wallet-mcp`.

### Modified Capabilities
- `device-sessions`: в список сессий входят MCP-токены (`platform: "mcp"`), у
  сессий появляются время последнего использования и срок действия, отзыв
  одной сессии и `revoke-others` действуют и на MCP-токены.

## Impact

- **google-auth:** новые ручки `/auth/mcp-tokens` и `/internal/mcp/token`,
  новые записи в Redis (хэш токена → пользователь, `device_id`, имя, потолок;
  скользящий срок — TTL ключа), выпуск JWT с урезанными claim'ами,
  `openapi.yaml`, `README.md`, метрики выпуска и обмена.
- **wallet-gateway:** без правок. `/auth/*` уже проксируется, `/internal/*`
  нет, и так и должно остаться.
- **wallet-report:** без правок. Проверяет `aud` `wallet-report` и scope
  `reports:read`, как у любого токена. Токен без `role` — обычный пользователь.
- **wallet-mcp (новый сервис):** клиент `/internal/mcp/token`, кеш JWT до
  `exp` по хэшу MCP-токена.
- **wallet-web:** экран «Мои устройства» — выпуск MCP-токена (показ один раз,
  копирование) и отображение срока и последнего использования. Отдельный change.
- **Безопасность:** `/internal/*` защищён только сетью контура
  (`TODO_service_auth_tls.md`). `wallet-mcp` — второй внутренний клиент после
  бота, но ему общий секрет не нужен: доказательство — сам MCP-токен (256 бит).
