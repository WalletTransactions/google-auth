# Design

## Context

Access-токен пользователя несёт фиксированный `aud` и `scope` (спека `session-tokens`).
Гейтвей сверяет `aud` с адресатом маршрута, сервисы дополнительно проверяют `scope`.
Токены бота и обмена выпускаются отдельно и ограничены своими парами. См. proposal.md.

## Goals / Non-Goals

**Goals:**
- Пользовательский токен пропускается гейтвеем на `/api/docs/*`.
- Расширение токена не ломает ни один существующий сервис.

**Non-Goals:**
- Новые роли и новые claim'ы. Клиент (`android`/`web`) читается из уже существующего
  claim `platform`, а не из тела запроса: сервер не доверяет клиентскому полю.
- Проверка `role` и видимости спек: это делает wallet-docs.

## Decisions

**D1. Один общий токен, а не обмен.** Альтернатива — отдельный обмен токена пользователя
на токен для wallet-docs (как для wallet-mcp). Отвергнута: у wallet-docs нет вызовов
других сервисов от имени пользователя, а обмен добавил бы запрос на каждый вопрос и
связал бы клиенты с логикой обмена. Достаточно `aud`.

**D2. Выдавать адресата всегда, даже если wallet-docs не развёрнут.** Лишний элемент
`aud` безвреден: гейтвей без апстрима отвечает `404` до проверки токена. Условная выдача
по настройке сервиса сделала бы токен зависимым от состава контура.

**D3. `scope` `docs:ask`.** Следует схеме `ai:use`: адресат отвечает за «куда», scope за
«что можно». Бот и обмен его не получают.

**Потребители и порядок выкатки.** Токен читают wallet-api, wallet-report, wallet-ai,
wallet-mcp (игнорируют лишнее), wallet-gateway (`docs-route`), wallet-docs. Порядок:
google-auth → wallet-docs → wallet-gateway → клиенты. Правка в других сервисах не нужна,
кроме перечисленных change'ей.

## Risks / Trade-offs

- [Токен чуть больше] → +14 байт `aud` и +9 байт `scope`; на размер cookie это не влияет.
- [Клиенты, которые сравнивают `aud` на равенство, а не на вхождение] → в стеке таких нет;
  проверить поиском по `aud` в wallet-api/-report/-ai перед выкатом (задача 1.2).
- [Android присылает `platform` сам при входе] → допустимые значения ограничены
  (`android`, `ios`, `web`, `other`); для docs это подсказка, а не граница безопасности:
  админ определяется по `role`.
